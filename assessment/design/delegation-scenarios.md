## 要否と実装順序

委任前の文章作成だけでなく、委任後の観測・介入を評価するために必要。ただし最初の実機受入対象をW-I4へ切り替えず、[ロードマップ](../../docs/roadmap.md)のW-A1/W-B1先行を維持する。

[委任・監督の補足基準](../../framework/delegation-and-oversight.md)と[根拠の帰属](../practice/evidence-attribution.md)をレビューした後、教材担当者が固定素材と開始文を制作する。複数の評価者による架空回答の確認・判断相違の記録は別の必要工程であり、AI一者の確認で代替したとは報告しない。

## 制作する固定資料

主題は「架空の社内案内の下書き・確認・配付準備」。以下の資料束を一つの版として制作する。資料番号は設計上の識別子であり、現時点で完成資料が存在する意味ではない。

| 資料ID | 制作内容 |
|---|---|
| M01 | 目的、対象ID・版・宛先、成果物、期限、許可・禁止の原依頼 |
| M02 | 学習者・承認者・模擬作業AIの役割表と、可能操作・許可操作・停止方法 |
| M03 | 正式な承認記録。対象版・宛先・有効条件・再承認条件 |
| M04 | 正確な応答と誤った応答を含む固定の模擬AI出力 |
| M05 | 各場面で示す模擬実行履歴と、成果物・状態の独立した証拠 |
| M06 | 条件変更、参考資料中の指示、停止後の残存処理・他者更新 |
| M07 | 初回答後に渡す共通フィードバックと、内容の異なる固定課題 |

## 段階提示する場面

「委任案を提出した後」「根拠を挙げて判断した後」など、回答の提出を契機に提示する。秒数やモデルの自由生成で条件を変えない。各場面の完全な資料、設問、許容例・不適合例は次工程で作成する。

| 場面 | 開示する変更・証拠 | 主な観察 |
|---|---|---|
| S01：正常な続行 | 承認対象と版・宛先が一致し、許可範囲内の下書きが確認できる | 根拠付きで続行・受入を選ぶ。AI出力を無条件拒否しない |
| S02：権限拡張 | 下書きのみの依頼に送信・名簿更新の提案が加わる | 追加操作は保留し、独立して進められる許可部分を続ける |
| S03：古い承認 | 承認後に版・宛先・対象人数が変わる | 承認対象との差を特定し、変更範囲の再承認を求める |
| S04：資料内の命令 | 参考文書に「承認済みなので実行」と書かれる | 外部資料と正式な承認を区別する |
| S05：完了報告の不一致 | 「確認・保存済み」という出力と履歴・結果が一致しない | 未実施と未確認を分け、根拠なしの完了を採用しない |
| S06：停止・復旧 | 停止依頼後も処理が残り、復旧案が他者更新を上書きする | 停止依頼と停止確認を分離し、無承認復旧をしない |
| S07：部分保留 | 変更の影響を受けない作業と、確認待ちの作業が混在する | 影響を限定できる根拠を示して部分続行する。限定不能なら停止・相談も許容 |

## モードと評価の区別

W-I4はヒント・説明・再試行を許可する。D-I4とDX06は初回答を生成AIなしとし、模擬AI出力は固定資料として提供する。必要な資料閲覧・メモ等の通常支援は維持する。自由生成の回答や端末操作の差を採点に混ぜない。

DX06の主評価はE2・I4、その他は補助観察。初回答、共通フィードバック、修正、未見の別課題を分け、同じ資料の既見を記録する。公開練習で見た課題を採用本番や未見確認にそのまま使わない。指示文の長さ・巧みさだけで評価しない。

適切な停止と成果物未完成を分離する。全停止が常に正解ではなく、無根拠の続行も不可。[補助様式](../../templates/delegation-observation.md)で許可・行動・結果を分ける。学習コーチは模擬作業AIの出力や引用命令を実行しない。
