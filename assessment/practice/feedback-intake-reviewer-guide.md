# フィードバック活用と読解・要件整理：人間の確認ガイド

確認基準版：0.1-draft。対象は[W-E2](../../learning/W-E2/README.md)、[遅延確認Y01・Y02](../../learning/W-E2/delayed-check.md)、[DX01](DX01.md)。W-E2はE2、DX01はA1/B1が主評価であり、相互の事前・事後テストとして使わない。全内容は試作で、人間2名の校正、実機、学習効果、A/B難度同等性は未確認。

## 確認方法
評価担当者は本人の原回答・原資料・全支援・修正を同じ参照コミットで確認する。[評価原則](../../framework/assessment-principles.md)と[根拠の帰属](evidence-attribution.md)に従い、AIの記録案だけで評価しない。表現差と内容の不一致を分ける。必要な読み上げ等の利用、文章量、同調、回答速度を人格・能力の代理指標にしない。

通常利用はmainの承認版を固定し、PRは該当なし。未マージ版は実在PR・head branch・コミットを記録する。実行者は人間の評価者、環境は会社承認済みの非公開記録先、実施時点は利用目的・支援・記録範囲の承認後。AIは参考コメントまで。変更対象は新規の確認記録で、本人の原回答・公開資料・確定評価・会社設定を上書きしない。

## W-E2：原資料に基づく確認
| 対象 | 許容する判断・根拠 |
|---|---|
| DOC21・v2 | 保存済みだが確認未着手なので更新未完了。依頼受付を完了としない（E2-R01・R02） |
| DOC22・v3 | 保存と対象版の人間確認があり完了。正しい報告を保持する |
| DOC23・v2 | 保存は確認できるが、v2の確認結果は収録されていない。v1の確認ではv2の更新完了を証明できない。完了を未確認として人間の確認担当へv2の結果を尋ねる。v2の未実施や不合格まで断定しない |
| DOC24・v4 | 対象限定のEX24、文言不変・参照番号修正、v4保存・本人点検が揃うので簡易条件で完了。人間の通常確認がないことだけで未完了にしない |
| Q2 | F01をDOC21だけでなくDOC23の対象版不一致にも適用し、DOC22・DOC24を維持する理由を説明。初回答・支援・修正を別記する |
| Q3 | 全件未完了という追加助言は適用範囲を広げ過ぎている。正しい記録と対象限定例外を根拠に修正量を限定する |
| X01 | KIT31は準備未完了、KIT32・KIT33は準備完了。3件とも受渡し未実施。通常の完了条件と電子方式の別条件を読み替える（E2-XR01・XR02） |

DOC23は「更新完了とは報告できない」と記載する別表現も許容するが、未実施と断定するか、結果未確認と限定するかを確認する。「全件完了」や「全件未確認」に機械的にそろえない。

### E2の観察単位
| 観察 | 本人のどの回答を見るか | 解釈上の限界 |
|---|---|---|
| 初期の方法 | Q1とその支援記録 | 固定報告案は本人の誤答ではない |
| 指摘理由の理解 | Q2の規則とDOC21の修正理由 | AIの解説を貼っただけでは本人の理解としない |
| 類似箇所・例外 | Q2のDOC23、DOC22・DOC24の維持理由、Q3 | 修正数の多さでは評価しない |
| 同日の別場面 | X-Q1の根拠と完了条件の読み替え | 既見なら未見転移としない。主課題と同じ独立性ではない |
| 別日の適用 | Y01・Y02の回答と実際の間隔 | 公開問題の既見、支援、未実施を明示。一般的な効果保証ではない |

初回答ですべて正しかった場合、E2の改善量はこの課題では測れない。誤りを作らせず、保持理由・例外判断・別場面の行動を記録する。指摘前後で変化しなかったという理由だけで低評価にしない。

## 遅延確認の期待判断
| 問題 | 正しい部分・修正・未確認 |
|---|---|
| Y01・REQ41 | 登録済みだが通知未送信なので通常の受付完了には未到達（Y1-R01・R03） |
| Y01・REQ42 | 登録・送信成功により受付完了。配達・閲覧は未確認で、「相手が読んだ」は採用しない |
| Y01・REQ43 | 窓口方式の必要記録が揃い受付完了。不要なメール送信を要求しない（Y1-R02・R03） |
| Y02・RET51 | 受領済みでも状態点検は未実施なので返却整理未完了（Y2-R01・R03） |
| Y02・RET52 | 通常条件を満たし返却整理完了。維持する |
| Y02・RET53 | 簡易対象、受領・封印確認が揃い返却整理完了。開封点検を足さない（Y2-R02・R03） |

Y1-Q2・Y2-Q2では、単語「確認」を反復しただけでなく、対象ごとの完了条件と実施証拠を対応付ける方法を本人が説明しているか確認する。実施日・既見・支援を確認できなければ「遅延で保持した」という結論を保留する。

## DX01：A1とB1を分けて確認
| 設問 | フォームAの観点 | フォームBの観点 |
|---|---|---|
| Q1（A1） | 職員が備品・受取方法を選べる目的、下書きと根拠メモ、EQ31/32、EQ33/34除外、4月7日15:00、総務責任者、実操作なし、EQ32場所未確定 | 確定団体が集合できる目的、案内下書きと確認メモ、GR41/42のみ、開催5月20日と提出5月12日12:00、各集合時刻・西門受付、駐車場未確定、配信なし |
| Q2（A1） | A-R02は見出しのみ参照可。全件掲載・推定記入・当日公開を採用しない。施設担当へEQ32の確定受取場所を質問 | B-R02の西門受付と見出しは継続。全員09:00・未確定団体配信・P2の利用を流用しない。施設担当へ今回の駐車場利用可否を質問 |
| Q3（B1） | 掲載範囲、必要3項目、原文照合、不明点と確認先が揃うことを下書きの完了条件にする。公開は確定と別承認を要する | 対象・開催日・団体別時刻・場所・駐車場確認待ちと確認メモを照合する。配信条件を下書き提出条件へ混入させない |
| Q4（B1） | 確定情報で下書きを作り、EQ32場所は確認待ち。目的への対応と確認依頼案を示す。施設回答や提出済みを捏造しない | GR41/42の確定時刻・西門受付を使い、駐車場のみ確認待ち。全停止せず、配信もしない。参加団体の迷いを減らす目的に結ぶ |

模範の語句や文章構成との一致は要求しない。必要条件を満たす別解を認める。確認待ちの明示を含む下書き提出が許されているのに、「一つ未確定なので何もできない」とする回答は再確認対象。一方、下書き完成を公開・配信の許可とは扱わない。Q3/Q4の論拠としてQ1/Q2を参照しても独立した実施回を増やさない。

## 中止・復旧
版・資料・支援条件が不一致なら評価確定を止める。根拠不足はU、職務上の対象外は承認を要するNAとして区別し、0へ置換しない。失われた初回答は推測復元しない。教材の修正は[PR](../../CONTRIBUTING.md)で行い、原記録を残して別日に再確認する。期待結果は根拠に対応した観察であり、全社員配付・採用用途の承認は別工程である。
