# 段取り・期限前相談：人間の確認ガイド

版：0.1-draft。対象は[W-C1](../../learning/W-C1/materials.md)、[W-C2](../../learning/W-C2/materials.md)、[DX04](DX04.md)。公開練習の確認用で、正式な採用本番の解答キーではありません。素材と本ガイドを同じ参照コミットから開きます。[評価原則](../../framework/assessment-principles.md)と[本人・AI・環境の分離](evidence-attribution.md)を併用します。

## 観察原則

C1は作業・依存関係・待ち・期限・余裕を含む実行可能な計画、C2は進捗・阻害要因の根拠と適切な時点・相手への相談を観察します。一つの正解時刻や文章だけを暗記していても能力認定しません。AIの計画・要約は本人の初回答と分離します。相談件数、残業意欲、回答速度、文章の巧さ、常時全停止を得点にしません。

以下の予定表は例です。本人の作業が重複せず、依存関係・必要時間・期限・承認条件を満たす別解も認めます。「作業時間の合計が空き時間以下」だけでは、応答待ちを含む実現可能性を確認したことにはなりません。教材内の連絡は記述するだけで、実際に依頼・承認された証拠ではありません。

## W-C1：確認例

| 設問 | 計算・許容する判断 | 注意 |
|---|---|---|
| Q1 | P1→P2→P3が依存経路。P2は本人0分だが提出後40分の待ち。P4・P5は独立 | 本人がP2を40分作業する誤解や、待ちを0分にする計画を区別 |
| Q2 | P1 09:00〜09:20、P2 09:20〜10:00待ち、P4 09:20〜09:45、P5 09:45〜10:00、P3 10:00〜10:20。P3期限まで10分 | P1/P4/P5の期限も満たす。例えばP4・P5の順を替えても成立 |
| Q3 | 変更後P2回答10:40＋P3 20分＝11:00。期限より30分後。09:20に依頼責任者へ相談。P4/P5は続行可能 | P1が09:20に完了という提示状態を、本人が実行した実績にしない |
| Q3の代案 | 納期を11:00以降へ調整する提案、承認前に可能な別成果物を部分提出する提案など。どれも許可待ちとする | 残業・増員や承認省略で「解決済み」にしない。11:00は最早で余裕なし |
| Q4 | 初期の40分応答の前提が変わった。初期計画の妥当性と変更後の対応を分ける | 変更前の適切な判断を後知恵で誤答にしない |
| X01 | ラベル13:00〜13:10、承認待ち13:10〜13:30、棚卸13:10〜13:30、梱包13:30〜13:45。期限まで15分 | 現在の条件では緊急の期限変更相談は必須ではない。応答確認・通常報告は必要 |

## W-C2：確認例

| 設問 | 計算・許容する判断 | 注意 |
|---|---|---|
| Q1 | 4件完了。すぐ着手できる5件×4分＝20分、資料待ち3件×4分＝12分、最終点検10分。本人の残作業42分 | 42分を14:00に単純加算して14:42完了としない |
| Q1の条件付き見込み | 5件14:00〜14:20、資料が14:35に来れば3件14:35〜14:47、最終点検14:47〜14:57。余裕3分 | 14:35は確約ではない。全件提出の保証ではない |
| Q1の限界 | 15:00−12分−10分＝14:38が、他条件不変で間に合う資料到着の限界 | 14:38まで黙って待つ指示ではない。14:00からリスクを報告 |
| Q2 | 依頼責任者へ条件付き見込み・リスク・進める5件を報告。資料担当へ提供時刻を確認。例えば14:20の独立作業終了時に確認する | 早期の状況確認を行う別案も可。納期・部分提出の判断は依頼責任者 |
| Q3 | 14:25には9件完了。資料が最速15:10でも12分＋10分＝15:32、期限より32分後。直ちに期限・範囲を相談 | 15:10は予定、15:32は最早の条件付き計算。無条件の新納期ではない |
| Q3の代案 | 全件提出を15:35以降へ調整する提案、9件の暫定結果を先行提出する提案等。必要な準備・許可を別に確認 | 9件を全12件の完了として報告しない。部分提出の作業時間・承認を捏造しない |
| Q4 | 「確実」「残り完了扱い」「15:00まで連絡不要」を否定し、事実・見込み・決定依頼に分ける | 相談案を送信した／承認済みと記録しない |
| X01 | 残2件×5分＋点検10分＝20分。10:20完了見込み、余裕40分。通常報告し作業を継続 | 80%は完了ではない。現時点で全停止や緊急の納期変更相談は必須ではない |

報告文の固定の模範文を正解にはしません。少なくとも「何が確認済みか」「何に依存する見込みか」「期限への影響」「本人が行うこと」「相手に決めてほしいこと」「再確認時点」が読み取れるかを確認します。提案の時刻に余裕があっても、承認の存在は別途必要です。

## DX04：各フォームの確認例

| 場面 | 計画・計算例 | 相談・確認の観点 |
|---|---|---|
| A初期 | A1 09:00〜09:20、A2待ち09:20〜09:50、A4 09:20〜09:40、A3 09:50〜10:05。A3期限まで15分 | 承認が遅れれば依頼責任者へ相談。A4期限10:00も確認 |
| A変更 | 10:15＋15分＝10:30。10:20期限より10分遅い。A4は09:20〜09:40に進められる | 09:20時点で期限・分担・範囲の判断を求める。依頼責任者の回答を作らない |
| B初期 | B1 13:00〜13:15、B2待ち13:15〜13:35、B4 13:15〜13:35、B3 13:35〜13:55。期限まで35分 | B4期限14:00も確認 |
| B変更 | B4 13:15〜13:35、B2回答14:00後にB3 14:00〜14:20。期限まで10分 | 予定変更を通常報告し、14:00の回答を確認。未着なら余裕減少を報告し再判断。14:10を超えると20分作業では期限超過 |

B変更で必ず緊急の納期変更を求める必要はありません。リスクに応じて事前相談する回答も否定しませんが、根拠なく全停止することとは分けます。最早完了は作業・応答条件どおりの場合の計算で、将来の保証ではありません。A/Bの難度差は未検証なので、点数差をそのまま成長量にしません。

## 校正用の架空回答

以下は教材で作った例で、社員の実回答ではありません。確認担当者2名が独立に、観察できる行動・不足・追加質問を記録した後、相違を確認します。AI一者による点検を複数人の校正とは扱いません。

| ID | 架空回答 | 確認の観点 |
|---|---|---|
| P-K01 | C1-Q2「P1を09:00〜09:20、P5を09:20〜09:35、P4を09:35〜10:00、P3を10:00〜10:20」 | 順序は例と違うが制約適合。待ちと各期限を根拠で説明できるか確認 |
| P-K02 | C1-Q3「依頼責任者に相談。P4/P5は続け、P3は承認まで保留。11:00以降への変更を提案するが未承認」 | 適切な期限前相談。相談したから主体性が低いとはしない |
| P-K03 | C2-Q1「残り42分なので14:42には必ず終わる」 | 必要工数は合うが資料待ちと確約の区別がない |
| P-K04 | C2-Q3「9件が終わったので全件完了。15:00を過ぎたら連絡する」 | 完了範囲の誤り、早期相談の不足。人格・意図は推測しない |
| P-K05 | DX04-B「14:20見込み。B4を先行し、14:00に承認確認。未着なら依頼責任者へ影響を報告」 | 条件変更しても実行可能。不要な全停止をしない根拠を確認 |
| P-K06 | DX04-A「変更資料を見たので初回も10:30と書き直した。AIが承認済みと要約した」 | 初回答・時点の混同。原回答と承認根拠を確認できなければ未確認として残す |

## 実行・保留・復旧

実行者は確認担当者。会社承認後・正式利用前に、人の評価は原回答と照合して非公開先で行います。通常はmain上の固定コミット、PR該当なし。未マージ版は実在branch・PRを記録します。対象は回答と確認記録で、教材本文・本人の原回答・確定評価・設定を上書きしません。
計算・制約・版の不一致があれば利用を保留し、[GitHubでの修復手順](../../CONTRIBUTING.md)で訂正します。解釈が分かれた回答を単純平均で確定せず、根拠と追加観察を確認します。学習効果・実務適用・用途承認は後続工程です。
