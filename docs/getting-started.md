# GitHubから教材を参照して試行する

教材の参照・コピー・版の確認・復旧は、このリポジトリのGitHub画面で行います。PC内の保存先指定、ダウンロード・展開、Gitのインストール、過去の配布資料は必要ありません。

**GitHubで完結させるのは公開文書と教材の参照・管理です。** 学習コーチはGeminiで実行し、個人の回答・学習記録は会社が承認した制限付きGoogle Workspaceに保存します。公開リポジトリへ個人記録を記入しません。

## 前提・対象

| 項目 | 内容 |
|---|---|
| 実行者 | 教材確認担当者。全社員配付の前に架空資料で受入試行する |
| 実行環境 | 会社管理PCのブラウザ、GitHubの公開ファイル画面、会社Google WorkspaceアカウントのGemini通常チャット |
| リポジトリ | [itdojp/workplace-competency-framework](https://github.com/itdojp/workplace-competency-framework) |
| 対象branch | 通常の参照開始点は`main`。実行する教材は同一のコミットに固定する |
| 対象PR | 教材を使うだけの場合は該当なし。未マージ版を確認する場合のみ、実在するPR番号・head branch・コミットを記録する |
| 実行時点 | 管理者によるGemini利用可否、記録の保存先・共有範囲の確認後。正式評価・全社員配付の前 |
| 変更対象 | 新規の架空試行チャットと、承認された非公開の本人用記録 |
| 変更禁止対象 | 教材・評価基準の原本、会社設定、実際のメール・会議・フォーム、社員名簿、正式評価、既存の運用ファイル |
| 期待結果 | 固定した教材に従って初回答、根拠確認、支援、修正、別場面へ進み、事実に一致する記録案を得る |

会社アカウントでGeminiを利用できない場合は開始せず、管理者へ確認します。個人アカウントへの切替、追加課金、Beta一括有効化は行いません。実際の保存先URLと確認担当者は社内で決め、公開Issueには記載しません。

## 利用する版を固定する

1. `main`で開始文を開きます。GitHubのファイル画面で`y`キーを押すと、URLのbranch名がコミットIDに置き換わります。キー操作が使えない場合は、ファイルのHistoryから対象コミットのファイル表示を開きます。
2. コミットIDとファイルの固定URLを記録します。確認基準・受入確認・記録様式も同じコミットから参照します。途中で更新された`main`の別ファイルを混ぜません。
3. 固定した開始文の画面でRawを開き、本文全体をコピーします。ファイルの保存は不要です。コピー対象は開始文だけで、GitHub画面のメニューや別資料を含めません。

本文の教材版とコミットIDは別の情報です。教材版が同じでも文書修正でコミットは変わります。`main`へマージ済みであることは、実機受入済みを意味しません。

参考：[GitHubのコミット固定リンク](https://docs.github.com/en/repositories/working-with-files/using-files/getting-permanent-links-to-files)。

## 実行環境の事前確認

教材確認担当者は、試行前に管理者または権限を持つ確認者と[実行環境・停止手段の確認票](../tests/coach-behavior/runtime-preflight.md)を確認します。AIの自己説明ではなく、実施時点の公式資料・会社画面で確認できた範囲を非公開記録へ残します。行動テストの適合と、環境の権限制限・停止確認は別です。

重要な範囲や停止手段が未確認なら通常の開始と全社員配付を保留し、管理者へ確認します。観測不能な点を明記した架空資料限定試行を管理者が別途承認する場合だけ、その条件で試行できます。利用者が設定変更・権限取得・本番操作で確認してはいけません。

## W-A1の試行

1. 会社アカウントでGeminiの通常の新規チャットを開きます。
2. 固定した`learning/W-A1/start.txt`の全文を最初のメッセージへ貼り付けます。ファイル添付、Gems、Skills、外部連携は使用しません。
3. 期待する初回表示はW-A1、0.2-draft、原資料[1]～[7]、Q1だけです。正解や全設問の回答が先に出たら受入不適合として記録します。
4. 初回答、根拠確認、必要な支援、修正理由、別場面へ進みます。20分は目安です。支援を使ったことや中断だけで能力を低く評価しません。
5. 終了時は「記録を出して終了」と伝え、記録案を会話と照合します。初回答、支援、未実施が改変されていないことを確認します。[空テンプレート](../templates/learning-record.md)の項目を承認された非公開の記録先へ写し、本人が記入します。GitHubのテンプレートを直接編集して個人の回答を保存してはいけません。AIの「保存済み」という発言だけで保存を完了扱いにしません。

## W-B1の試行

W-A1の受入結果を確認した後、同じコミットの`learning/W-B1/start.txt`をGitHubでRaw表示し、全文を別の新規チャットへ貼り付けます。期待する初回表示はW-B1、0.2-draft、主資料7文、Q1だけです。

主資料はW-A1と同じです。既見資料の成功を未知課題の独立証拠として数えません。

## エラー時・復旧

| 状況 | 停止・分岐 | 復旧 |
|---|---|---|
| ファイルが開けない、版が一致しない、コピーが途中で切れる | 不完全な開始文を実行しない | 記録したコミットのGitHubファイルを再表示し、Rawから全文をコピーして新規チャットで再開する |
| 初回解答の先出し、原資料の改変、実操作の要求、架空の保存報告、初回答の書換え | その試行を能力確認に使わず停止する | 教材ID・版・コミット・問題箇所を確認担当者へ伝える。指導仕様の修正と再試験は別のPRで行う |
| 教材本文を誤って編集した | 未コミットの編集は破棄する。変更PRはマージしない | コミット済みならGitHubのHistoryで変更前を確認し、[変更手順](../CONTRIBUTING.md)に従って修復PRを作る |
| 会話や本人の回答が失われた | 失われた内容を推測復元しない | 残っている確認済み記録を使うか、新規試行とする。継続を初回独力評価と混同しない |
| 個人情報を誤共有した | 追加の共有を止めて情報管理担当者へ報告する | [公開方針](publication-policy.md)に従う。GitHubの履歴に残った情報を、最新ファイルから消しただけで回収済みとしない |

公開Issue・PRに記載するのは、教材の固定URLと架空の再現入力による不具合報告だけです。社員・応募者の実回答、会話、評価、内部保存先を貼りません。

既承認の実機適合版がない間は、全社員配付へ進みません。不適合版の代わりに使用できる承認済み版がある場合だけ、そのコミットを指定して再試行します。版がなければ担当者の試行に留めます。

## 一時方式と後続作業

一時方式はGemini通常チャットへの全文貼付けです。恒久方針は教材・指導仕様・記録・実行基盤の分離です。Gems/Skills対応、実機受入、全社員配付、Googleへの自動記録は[開発計画](roadmap.md)で別作業として管理します。
