## 3. 会社Googleの確認と接続

本人はブラウザ右上のアカウントで、会社が承認したWorkspaceアカウントにログインしていることを確認します。個人Gmailしか使えない場合は会社への配置を保留します。Google接続の状態は変わるため、毎回書込み前に実アカウントを確認します。

ChatGPTからの構築を利用する場合は、ChatGPTの設定の「プラグイン」または「アプリ」からGoogle Driveの接続管理を開き、利用可能なアカウント追加・変更操作で会社アカウントを選びます。Googleの認証・権限確認は本人が行います。変更手段が表示されない場合は操作を止め、表示されている接続管理項目を確認します。既存の別アカウントを黙って解除したり、会社資料を個人アカウントへ移したりしません。

この試行のために、管理者管理の同期、サービスアカウント、秘密鍵、全社Beta参加を新設しません。通常の個別接続と会社側の許可範囲を確認します。認証が会社ポリシーで拒否されたら、その制御を回避せずWorkspace管理者が必要な許可を確認します。参考：[Google Drive接続の公式手順](https://help.openai.com/en/articles/10929079-google-drive-app-and-setup-in-chatgpt)、[接続管理](https://help.openai.com/en/articles/11487775-connected-apps-in-chatgpt)。

保存先は、新規の検証専用フォルダー名 `ITDO_職務能力開発_検証用` を提案します。実際のフォルダーURLは未設定です。作成者と指定された確認者だけが使える共有範囲にし、「リンクを知っている全員」や組織全体への公開にはしません。親フォルダーの共有も確認します。不要な継承共有がある場合は、その場所で続行しません。

承認の対象は「架空データだけ・新規検証ファイルだけ・外部共有なし」です。閲覧者、保存期間、検証終了時の取扱いは管理者が決めます。会社接続確認後の作成をエージェントへ渡す場合は、承認したフォルダーの実際のURLと変更範囲を非公開の会話で指定します。URLは認証を代替しません。パスワード、MFAコード、トークンは渡しません。

## 4. 10行の記録確認：手動で行う場合

この節は、会社接続を使うエージェントに委任せず、担当者がGitHubの原本から構築する場合の手順です。過去の会話添付やローカルフォルダーを必要としません。

### 4.1 新しい検証ファイルを二つ作る

会社Google Driveから新しいスプレッドシートを作り、次の名前を使用します。

- `ITDO_管理者記録_検証10行_r2`
- `ITDO_個人学習記録_検証10行_r2`

どちらも担当者だけの検証用です。本人用検証ファイルにも架空2名分を入れますが、実際の社員へ配る本人用ファイルは1人1ファイルとし、他人の記録を入れません。各ファイルの実際の完全URLは作成後に非公開記録へ保存します。

管理者用は「案内・設定・能力・参照版・対象者・要求・根拠・評価根拠・評価・育成」、本人用は「案内・設定・能力・参照版・学習」のタブを先に作ります。タブ名は完全一致、各タブは少なくとも501行、評価はAD列まで確保します。

### 4.2 原本と数式を入れる

[構築原本一覧](../templates/spreadsheets/v0.1/README.md)の同じコミットから各TSVをRaw表示し、全文を対応タブA1へ貼り付けます。ヘッダーと数式列の位置を照合します。1セルにまとまる、数式が文字のまま、参照タブが見つからない場合は入力を止め、区切り・表示形式・タブ名を修正します。

**この初回確認では通常手順の100件への展開に代え、設定B3を両ファイルで`11`にして、2〜11行の10件分だけ数式を展開します。** 参照式の上限501行は変更しません。B3は自動的に数式を増減する機能ではないため、次の各範囲を実際に選択して下方向にコピーします。入力列は選択しません。

| ファイル | タブ | 選択して下方向へコピーする範囲 |
|---|---|---|
| 両方 | 参照版 | F2:F11 |
| 管理者 | 対象者 | E2:E11 |
| 管理者 | 要求 | V2:X11 |
| 管理者 | 根拠 | Q2:S11 |
| 管理者 | 評価根拠 | C2:H11 |
| 管理者 | 評価 | T2:AD11 |
| 管理者 | 育成 | V2:Z11 |
| 本人用 | 学習 | S2:W11 |

Windows/ChromeOSはCtrl+D、MacはCommand+Dが下方向コピーです。反応しない場合はブラウザのブックマーク操作等が実行されていないか確認し、Google Sheetsのメニュー検索から下方向コピーを選びます。参考：[Google公式のショートカット](https://support.google.com/docs/answer/181110?hl=en)。

[入力規則](../templates/spreadsheets/v0.1/validation-rules.csv)は最初の2〜11行だけに設定し、候補外は拒否します。日付列・ID列の型も既存手順どおりにします。数式の貼付けだけで入力規則が作られたとは扱いません。案内の記録枠表示を10に揃え、表示だけでなく11行目の数式を確認します。

### 4.3 架空入力を貼り付ける

[コピー用の架空入力](../tests/spreadsheets/smoke-inputs.md)を、各見出しの指定タブ・指定範囲へ貼り付けます。ブロックにヘッダーはなく、貼付け開始はA2です。管理者の対象者・参照版・要求・評価・根拠・評価根拠・育成、本人用の参照版・学習を入力します。本人用に管理者の評価・根拠をコピーしません。

日付のシリアル値は架空入力のまま扱い、設定B6は一旦空欄にして期限超過の判定を混ぜません。元データの承認・照合フラグは計算条件を確認する架空値で、実際の承認へ転用しません。貼付けによって入力規則が消えていないか確認します。

### 4.4 最初の期待結果と異常系

| 確認場所 | 正常入力での期待結果 |
|---|---|
| 管理者の案内 A5 / C5 / E5 / G5 | 4 / 4 / 0 / 0 |
| 管理者の案内 B12:C18 | 順に2/2、2/2、8/8、8/8、4/4、2/2、1/1 |
| 管理者の案内 D12:D18 / B20 | すべて「整合」 / 0 |
| 評価 Y2:Y5 | すべて「人間確定（形式確認）」 |
| 評価 Z2:Z5 | 1、0、2、0 |
| 育成 Z2:Z3 | すべて「完了（人間確認）」 |
| 本人用の案内 A5 / C5 / E5 / G5 | 6 / 6 / 0 / 0 |

以上はローカルの架空入力による期待値です。Googleの実測欄は未記入です。「人間確定」表示を実際の社員の評価・会社の用途承認とは扱いません。

正常表示を非公開記録へ残した後、管理者の「評価」S3を`EV-NOT-EXIST`へ変更します。期待結果はAC3とY3が「前回ID不一致」、AD3が「評価確認待ち」、Z3が空欄、案内C5が3です。育成Z2は「評価・根拠の紐付け不一致」になります。続いてS3を元の`EV-T-0`へ戻し、正常表示へ復旧することを確認します。この変更は架空の検証コピーだけで行います。

数式エラーや期待値不一致があれば、ファイル名・タブ・セル・入力・実測値・表示時刻を非公開記録へ残して保留します。100行への拡張は行わず、原記録を保持して新規コピーで訂正します。10行での適合後も、100行・500行の性能と復旧は別の受入です。

## 5. W-A1：まず一回の対話を確認する

実行者は教材確認担当者本人。環境は会社アカウントのGemini通常チャットです。先に[環境事前確認R01〜R06](../tests/coach-behavior/runtime-preflight.md)を確認し、重要事項が未確認なら通常の試行は保留します。文書にある架空資料限定の別承認を使う場合も、管理者が範囲と根拠を記録します。

[W-A1開始文](../learning/W-A1/start.txt)と[人間の確認ガイド](../assessment/practice/reviewer-guide.md)を同じコミットで参照します。開始文のRaw全文を新規チャットへ貼り付け、本人が最初の設問へ回答します。一度「ヒントをください」と求め、支援後の修正と理由を回答し、最後に「記録を出して終了」と伝えます。

教材ID・版・表示モデル・実際の実施日を本人が記録します。初回答を先に作らない、原資料の条件を変えない、支援と本人回答を分ける、未実施の保存・送信を報告しないことを確認し、記録案を実際の会話と照合します。一回の確認は全20項目の受入や学習効果の確認ではありません。

外部資料の参照、解答先出し、原回答の改変、架空の保存報告があれば中断し、原記録を非公開で保持します。会社の実データを入力しません。正常な最初の一巡後に[受入20項目](../tests/coach-behavior/acceptance.md)へ広げ、W-B1を続けます。恒久修正はPR、修正後は新規チャットで再確認します。
