# スプレッドシート用の空の記録様式

公開しているCSVはUTF-8のヘッダーのみです。GitHubのファイル表示から列名と列順を確認できます。個人情報もサンプルの個人評価も含みません。PCへの保存、リポジトリ外のブック、過去の配布資料は前提にしません。

| 用途 | リポジトリルート相対パス | 入力後の共有範囲 |
|---|---|---|
| 学習記録 | [templates/spreadsheets/learning-records.csv](learning-records.csv) | 本人と確認担当者 |
| 根拠記録 | [templates/spreadsheets/evidence.csv](evidence.csv) | 必要な評価担当者 |
| 能力評価 | [templates/spreadsheets/evaluations.csv](evaluations.csv) | 必要な評価担当者 |
| 育成計画 | [templates/spreadsheets/development-plans.csv](development-plans.csv) | 必要な担当者 |

**数式、入力規則、自動集計を備えたブックは本リポジトリでは未提供です。** CSVや列名をコピーしただけで、それらが実装されるわけではありません。

## 参照と利用

実行者は会社の評価管理者です。参照環境はGitHubのブラウザ画面、運用環境は会社が承認したGoogleスプレッドシートです。参照開始点は`main`とし、[導入ガイド](../../docs/getting-started.md)の方法でコミットを固定します。Google上の記録作業に対象branch・PRはありません。テンプレート自体の改訂は`main`に対する別PRで行います。

実行時点は、非公開保存先、共有者、利用目的、保存期間を承認した後です。変更対象は新規の制限付き管理ファイルだけで、GitHubの空テンプレートや既存の運用ファイルを個人記録で上書きしません。

GitHubに表示された列名を列順どおりに、用途別の新規スプレッドシートへ設定します。Raw表示からヘッダーをコピーすることもできます。カンマ区切りの1行を1セルに貼り付けただけでは、列設定は完了していません。公開CSVと列名・列数・順序を照合し、必要な入力確認を管理者が設計してから、個人の実データを入力します。

次節の2列を各行へ記入・照合した後の期待結果は、参照したコミットと列定義を行単位で追跡でき、用途ごとに閲覧者を限定できることです。非表示シートや編集保護を閲覧権限の代わりにしません。列や共有範囲が一致しなければ入力を止め、同じコミットのCSVから再確認します。復旧のために作り直す場合も新規の非公開ファイルとし、既存記録を消しません。誤共有時は共有解除と会社の事故対応を優先します。

## 各行に残す参照版

4種類のCSVの末尾には、`参照コミット`と`参照固定URL`があります。記録を別ファイルへ移しても版を追跡できるよう、**各データ行に固定値として記入**します。ファイル名や共通セルにだけ記録する方法、最新の`main`から値を取り直す数式では代替しません。

| 列 | 記入する内容 |
|---|---|
| 参照コミット | その行の作成に使用した列定義・能力定義・教材の参照版を表す40桁のコミットSHA。branch名や省略SHAではなく、GitHubで確認した値 |
| 参照固定URL | その用途のテンプレートCSVを、上記と同じコミットで開いたGitHub固定URL。上表の4ファイルのうち該当するものを使用 |

新規運用では、テンプレート、[能力辞書](../../framework/competencies.csv)、[行動基準](../../framework/behavioral-anchors.csv)、使用する[教材](../../learning/README.md)を同じ承認済みコミットで参照します。固定URLは`https://github.com/itdojp/workplace-competency-framework/blob/{参照コミット}/{リポジトリルート相対パス}`の形式です。波括弧は形式の説明であり、記入時には実在するコミットと当該CSVのパスに置き換えられたURLをGitHubからコピーします。そのコミットから同時点の能力定義・教材もたどれます。教材版・能力辞書版の欄は従来どおり記入し、コミットの代わりにはしません。

記録時と人間による確認時に、次を確認します。

1. 参照コミットが40桁の16進数であり、固定URLの`blob/`直後のコミットと一致すること。
2. 固定URLが本リポジトリの該当CSVを開き、記録に使った列名・列順と一致すること。`main`、作業branch、タグのURLを代用しないこと。
3. 能力定義・教材を実際に参照した版であること。後日の転記時点の最新コミットを、実施時の版と偽って記入しないこと。

どれかが不一致・未確認なら、参照版を確認済みとして扱わず、記録の確定を止めて元の固定URLと実施記録を確認します。この確認は管理者が行う手順であり、CSVに自動検証は実装していません。

## 版の更新と旧記録

版を更新して再実施・再評価する場合は、新しい記録行に新しい参照版を記入します。過去の行の参照版を最新値で一括上書きしません。過去の根拠を新しい基準で評価する場合、根拠行は採取時の参照版を保持し、評価行は評価に用いた参照版と根拠IDを記録します。

追加2列がない旧様式を使っている場合は、既存記録を保持した非公開の作業コピーで、末尾に2列だけ追加します。既存の列名・列順・ID・値は維持します。当時の参照版を確認できる行だけ補記し、確認できない行は`参照コミット`を「未確認」、`参照固定URL`を空欄として、未確認のまま保持します。未確認は能力水準0を意味しません。現在のコミットを推測で補わず、確認できるまで参照版を要する評価の確定には使いません。

移行後は旧様式との行数・既存値・ID・共有範囲を照合します。不一致なら移行を止め、保持した旧記録を変更せずに修正用のコピーを作り直します。移行済みで列だけが増えた過去の行については、固定URLが移行前の列定義を示すことと、末尾2列のみの追加であることを確認します。個人記録のコピー・移行は会社の非公開環境だけで行い、本リポジトリには記入済みデータを追加しません。

## 評価と更新

未評価はU、対象外はNA、能力水準は0～3です。AIコメント案と人間の確定評価を分け、自己評価やAI提案を直接確定値にしません。証拠IDと評価IDは固定し、再評価は新しい行で保存します。実行日時・モデル名は本人が確認し、AIの推定値を使用しません。

[能力辞書](../../framework/competencies.csv)の変更はPRで承認し、承認済みの版をGoogle側へ反映します。個人データの自動同期はありません。記入済みのファイル、内部保存先URL、共有者一覧は[公開方針](../../docs/publication-policy.md)に従ってGitHubへ登録しません。
