# Googleスプレッドシート記録テンプレート v0.1

版：0.1-draft。対象は社員育成の試行記録。入力列、数式の原本、入力規則を公開する。Googleへの自動登録・自動保存、能力・採否の自動判定は実装しない。会社Workspaceでの受入は未実施。

## 実施条件と境界

実行者は会社の評価管理者。GitHubのブラウザで原本を参照し、会社が承認したGoogleスプレッドシートへ新規作成する。実施時点は会社アカウント、保存場所、閲覧者、目的、保存期間の承認後。正式な保存先URLと承認者は非公開記録に残す。個人Gmailしか接続されていない場合は、会社側への配置を保留する。アカウントを推測して作成・共有しない。

参照開始点はmainで、[導入ガイド](../../../docs/getting-started.md)に従って使用コミットを固定する。未マージ版のみ実在するPR・head branchも記録する。Google上の入力作業自体にbranch・PRはない。変更対象は新規の非公開管理ファイルと本人用コピーのみ。既存記録、公開CSV、教材本文、会社の権限・課金・全社設定は変更しない。

公開原本はこのディレクトリのTSVと入力規則。TSVはヘッダーと数式の種行を含み、ダウンロードやローカル環境を必要としない。バイナリ配布物や過去の会話添付を前提にしない。数式の正しさと、Google上の動作・権限・運用承認は別に確認する。

## ファイルとタブ

管理者用ファイルは「案内・設定・能力・参照版・対象者・要求・根拠・評価根拠・評価・育成」。
本人用ファイルは本人ごとに別ファイルとして「案内・設定・能力・参照版・学習」。本人用に管理者の根拠・評価・他の社員情報をコピーしない。非表示タブや編集保護を閲覧制限の代わりにしない。ファイルをまたぐ自動同期はない。

## 初期構築

1. 上記のタブをすべて先に作成する。数式を入れる前に参照先のタブ名を揃える。各タブは少なくとも501行、評価タブは30列（AD）を確保する。ロケールは日本、日付・時刻の扱いを会社内で統一する。
2. 対応するTSVを同じGitHubコミットでRaw表示し、全文コピーして該当タブのA1へ貼る。タブ区切りで各列に展開されたことをヘッダーと列数で確認する。1セルにまとまった場合や数式が文字として残る場合は入力を始めず、セルの表示形式を自動に戻し、貼付け・区切りを確認する。
3. 表の数式列について、2行目の数式を101行目まで下方向へコピーする。例えば評価はT2:AD101を選択して下方向へコピーする。入力列まで埋めるとIDや回答を複製するので行わない。能力・設定・案内の全体を下方向へ複製しない。
4. [validation-rules.csv](validation-rules.csv)どおり、データの入力規則を入力列の2～101行へ設定する。指定リスト以外は拒否する設定を基本にし、複数選択は使わない。日付列はyyyy-mm-dd、IDと参照コミットは文字列、数式列は自動形式とする。入力規則はTSVの貼付けだけでは作成されない。回答やコメントから数式記号で始まる文字列を転記する場合はプレーンテキストとして保存し、入力列に意図しない数式を実行させない。参考：[Google公式・プルダウン](https://support.google.com/docs/answer/186103)。
5. ヘッダー1行と左側のID列を固定し、数式列を入力列と別の色にする。数式列は管理者のみ編集可能にするか、編集時警告を設ける。これは誤編集防止であって閲覧権限の保護ではない。
6. 設定B6に実際の基準日を入力する。空欄なら再評価予定の期限超過は判定しない。参照版の確認者が、コミット・CSVの列・能力定義・教材の実在と版を照合し、確認日・対象範囲を記録してB列を「照合済」にする。事前入力の「未確認」を形式的に完了へ変えない。
7. このテンプレートを取得したGitHub固定URL・コミットも、運用ファイルの管理メモに残す。各行の参照コミットは教材・既存CSV列定義の参照版であり、追加数式の取得版を代替しない。共有先と保存期間を確認し、[受入確認](../../../tests/spreadsheets/acceptance.md)を架空データで実施してから実データを入力する。

期待結果は、入力の不足・参照版・ID連携を確認しながら診断から再評価を追跡できること。Google上での数式・入力規則・権限・コピー・復旧の受入前は、会社運用に適合した完成版とは扱わない。

## 診断から再評価まで

最初に「対象者」の本人IDとプロファイルIDを設定する。氏名は不要で、実際の本人対応表は適切な非公開先に分離する。「要求」は[職務別要求](../../../framework/role-requirements.md)に基づき設定し、要求IDをT列、必要な独立場面数をU列に付ける。最低場面数は会社が用途に応じて決める。教材が未制作という理由でNAにせず、対象外は理由と承認を要する。確認日は承認日Pから見直し日Qまでに入っている必要がある。

評価IDを先に採番し、対象者・能力・要求IDと使用版を入力する。根拠にはその原回答・場面・支援・本人とAIの区別を記録する。根拠のD列は初めて採取・登録した評価IDを保持する。複数根拠は「評価根拠」で1行1組の評価ID・根拠IDとして関連付ける。評価K列は代表根拠1件であり、カンマ区切りの複数IDを入れない。

根拠を別評価でも参照する場合、根拠の元行や採取時の版を変更せずリンク行を追加する。同一の対象者・能力を照合する。同じ評価内の同じ場面IDは複数根拠があっても1場面として集計する。場面IDを変えただけでは独立性を保証できないため、人間が課題・時点・支援を確認する。

人間が原回答を見てJ列の確認値とN列の確定状態を入力する。自己評価HやAIコメントIを自動転記しない。Y列「人間確定（形式確認）」は、人間の入力と形式条件が揃った表示であって能力認定ではない。AC列の前回ID不一致、その他の検査列の異常がある場合も確定作業を保留する。Z列の差は同じ条件での0～3同士だけを対象とする。U・NA・空欄を0へ変換しない。

不足がある場合も自動的に研修を割り当てず、技能・前提知識・指示・負荷・道具の原因を確認する。必要な1～2能力について「育成」を作成し、現状評価ID、根拠ID、具体的目標、ワーク、支援、別課題、再評価予定を決める。実施中と再評価待ちの合計が本人あたり設定B7を超えると警告する。

本人用「学習」は1設問・1段階を1行とする。セッションIDは設問間で再使用してよく、課題区分・設問IDとの組で重複を確認する。同じ設問の複数修正は試行番号を区別し、元の設問との関係を原記録に残す。本人が原回答の位置を確認してから転記する。学習内容の保存確認と習得は別。

再評価は新しい評価ID・新しい行で作成し、前回評価IDをS列に記載する。育成S列から新しい評価へ関連付ける。育成を完了にするには、学習記録の参照、再評価との対象者・能力・前回IDの一致、担当者による完了条件確認と確認者を要する。数式では学習記録参照の内容を読めないため、入力者の確認責任を残す。

## 参照版と過去記録

参照版タブはSHAの40桁・小文字16進数・重複を形式確認し、行の固定URLが所定のGitHub CSVと同じSHAを指すかを照合する。ネットワークでの実在確認・原資料の内容確認は担当者が行う。入力済みSHAや確認済フラグは、教材の用途承認を意味しない。

各行の固定URLは、既存列定義である[学習](../learning-records.csv)・[根拠](../evidence.csv)・[評価](../evaluations.csv)・[育成](../development-plans.csv)、または[職務要求](../../../framework/role-requirements-template.csv)を同じSHAで開いたURLとする。既存列を左側に保持し、本版の補助入力・数式は右へ追加する。追加列の取得版はテンプレート管理メモで追跡する。

能力マスタはa59545025fe339d0f85b0ce7e2aff4ca0b2c4217の固定スナップショットで、W-E2は未収録。この参照版が持つ11開始文だけをURL生成する。PR #29のmain反映で教材が増えても、過去行のSHAを一括更新しない。新しい運用コピーでマスタ・参照版を照合し、対応表の実在パスと版を管理者が更新する。記録SHAとマスタSHAが違えばURLの自動生成を保留し、同じコミットの対応表へ戻る。

過去データを新版で評価する場合は根拠を保持し、新評価の版を記載する。旧記録に参照版がなければ「未確認」のまま、推測で最新値を補わない。職務要求の変更は新しい要求ID・版として追加する。古い承認行を更新して過去評価の条件を変えない。

## 容量・式の破損・復旧

初期100レコード（2～101行）。102行以降を使う前に新しい非公開作業コピーを作り、すべての該当タブの数式・入力規則・書式・フィルターを同じ最終行まで延長し、設定B3を更新する。数式は501行までの参照枠を持つが、501行まで性能・操作性が検証済みという意味ではない。501行を超える場合は参照範囲を含む別改訂が必要。途中行への挿入・列移動・入力列だけの並べ替えを避ける。

案内の件数照合は、ID入力数と既知の検査結果数の違いを見つける補助。数式を同じ文字の定数へ置き換えた場合は検出できない。必ず原本の数式と列構造も確認する。異常のない件数だけで正しいとは判断しない。必須IDを落とした行、501行を超える入力、未登録の分岐も目視確認が必要。

入力不備・参照不一致・不正なID連携は確定を止め、担当者が原資料へ戻る。式の削除・破損は空原本から新規コピーへ再構築し、入力列だけを値として移してID・件数・元値・参照版を照合する。原記録は消さない。公開文書の修正は[PR](../../../CONTRIBUTING.md)、誤マージは履歴を保つ修復PRで戻す。誤共有は共有解除と会社の事故対応を優先し、revertだけで回収完了としない。

本人用・管理者用の共有はファイル単位。実際の権限、保存期間、処理速度、Googleの再計算・コピー・復旧は受入未実施。Gems/Skills、Apps Script、API、トリガー、外部リンクからの自動取込み、従業員の自動順位付け・採否決定は本版に含まない。
