# W-I4：任せる範囲と確認点を決める

教材版：0.1-draft。固定教材・開始文の試作。実機未検証、学習効果未検証、正式評価・採用本番には使用しない。

主評価能力はI4。H1・H3・C3等は同じ回答の補助観察であり、独立証拠を増やさない。人への分担や外注にも適用する考え方を、架空の作業AIの場面で練習する。

## 実行条件

| 項目 | 条件 |
|---|---|
| 実行者 | 初回は教材確認担当者。学習者への配付は受入・利用条件の確認後 |
| 環境 | GitHubブラウザと会社承認済みGemini通常チャット。紙面方式ではAIを使用しない |
| 参照branch・PR | 入口はmain。未マージ版だけ実在するPR番号・head branchを記録。いずれも参照コミットを固定 |
| 実行時点 | W-A1/W-B1の先行受入と、実行環境の事前確認後。教材制作は受入完了を意味しない |
| 変更対象 | 架空課題の回答と、許可された非公開学習記録のみ |
| 変更禁止 | 原資料、共有正本、送信・名簿更新、Google・GitHub設定、実データ、正式評価 |
| 期待結果 | 対象・許可・実行・結果の根拠を照合し、続行・保留・停止・相談とその理由を区別して記録する |

[導入ガイド](../../docs/getting-started.md)に従い、同一コミットの開始文をRawで全文コピーし、新しい通常チャットの最初のメッセージに貼り付ける。完全な参照先はGitHubのコミット固定URLとして記録する。会社画面での利用確認は[事前確認票](../../tests/coach-behavior/runtime-preflight.md)を使い、個人アカウントや追加課金へ迂回しない。

初回20分を目安にQ0〜S03を進め、S04〜S07とX01は必要に応じて別回へ分ける。短時間で全問完了することや支援なしを要求しない。S場面は独立したスナップショットであり、実操作の時系列ではない。

紙面方式は実施者がM01〜M03とQ0を提示し、初回答後にS場面を順番に示す。指導に使った観点・解説は記録する。公開ページや開始文には先の問題・確認観点が含まれるため、秘匿性のある試験にはしない。

## 記録と停止・復旧

初回答・支援・修正理由を、既存の根拠ID・場面IDと[補助様式](../../templates/delegation-observation.md)で関連付ける。参照コミット・教材版を残す。公開GitHubへ実回答・会話・内部保存先を書かない。

資料改変、答えの先出し、架空の保存報告、実操作要求があれば中断し、人間が原資料と照合する。失われた回答は推測復元せず、再試行を独力初回と数えない。誤った教材は配付を止め、GitHubの履歴で承認済みの固定版を参照する。利用できる適合版がなければ担当者の試行に留める。恒久修正は別PR、会社設定変更と自動保存は対象外。
