版：0.1-draft。固定教材の試作。実機受入・複数評価者確認・学習効果は未検証です。正式な能力認定や採用本番には使用しません。

## 参照するもの

[固定資料・設問](materials.md)、[通常チャット用開始文](start.txt)、[人間の確認ガイド](../../assessment/practice/source-reviewer-guide.md)、[専用受入確認](../../tests/coach-behavior/acceptance-source.md)。資料と開始文の固定資料区画は同じ内容です。既存の[W-A1・W-B1等](../README.md)とは版を分けます。

## 実行条件と操作

実行者：教材確認担当者。社員の練習は試行結果と利用範囲の承認後。実行環境：会社管理PCのブラウザ、会社Google WorkspaceアカウントのGemini通常チャット。一般知識の検索速度・特定のAI製品の操作技量を評価しません。

参照開始点はmainです。[導入ガイド](../../docs/getting-started.md)で承認されたコミットに固定し、同じコミットの本案内・資料・開始文・確認ガイドを開きます。完全な参照先はGitHub上で取得したコミット固定URLを記録します。通常試行に対象PRはなく、未マージ版を使う場合のみ実在するPR番号・head branch・コミットを記録します。PC内の保存・展開は不要です。

実行時点は[環境事前確認](../../tests/coach-behavior/runtime-preflight.md)と保存・共有条件の確認後です。W-A1→W-B1の先行受入と既存ワークの計画は省略しません。未確認事項がある場合は事前確認票の保留・限定試行の分岐に従います。

1. 上記の開始文をGitHubのRaw表示で開き、全文をコピーします。
2. Geminiの新しい通常チャットに全文を貼り付けます。Gems・Skills・API・Drive参照は前提にしません。
3. 設問へ一つずつ回答し、根拠と自分の説明を残します。20分は目安で、完遂や速さを強制しません。
4. 「記録」「中断」「終了」で記録案を出し、本人が会話と照合して会社承認済みの非公開先へ保存します。共通の[学習記録様式](../../templates/learning-record.md)の観察項目は使えますが、本ワークのID・版・設問に読み替えます。W-A1/W-B1のIDや0.2-draftを転記しません。

変更対象：新規チャット・非公開の学習記録だけ。変更禁止：公開教材、本人の原回答、正式評価、実在の社員・顧客情報、会社設定・権限・課金、外部サービスの実操作。期待結果：初回答と支援・修正・別場面への適用を根拠付きで残せることです。AIの要約だけを本人の能力証拠にしません。

## 観察と次の確認

主課題では受付日と利用日、発行日と適用日、正式資料と二次要約を分けます。別場面では新しい正式変更を適用するため、常に古い資料を選ぶ練習ではありません。

主課題・別場面を既に見た場合は既見として記録します。遅延確認は別日・未使用の課題で行い、通知は自動設定しません。[DX03](../../assessment/practice/DX03.md)は公開の別フォームですが、未見性・難度同等性・採用妥当性は保証しません。単独診断D-A4・D-D1は未制作です。

## 中止・復旧

条件改変、先行解答、外部操作要求、実施していない検索・保存の主張があれば試行を止め、原回答と発生箇所を非公開で保持します。人間が確認ガイドと照合し、教材に問題があれば[修復PR](../../CONTRIBUTING.md)で訂正します。開始文と資料を同じPRで更新し、版と参照も照合します。過去の回答は正解に上書きしません。

再試行は承認済みの同一版を新しいチャットへ貼り付けます。既に見た問題を初回診断として数えません。実機適合が確認された承認版がなければ全社員配付へ進まず、担当者の限定試行に留めます。誤公開は[公開方針](../../docs/publication-policy.md)に従い、通常のrevertで回収済みとはしません。
