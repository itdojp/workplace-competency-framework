対象はE2「フィードバック反映・学習転移」。教材版は0.1-draft。指摘された行だけの修正、同種の取り違えへの適用、例外と正しい部分の保持、別の業務への適用を分けて練習する。教材制作と静的確認は実機適合・学習効果の証明ではない。

## 実行条件と手順
実行者は本人、利用確認と記録確認は教材担当者。環境は会社が承認したGemini通常チャットと非公開記録先。[環境事前確認](../../tests/coach-behavior/runtime-preflight.md)と[導入ガイド](../../docs/getting-started.md)の条件を満たした後に試行する。W-A1→W-B1の先行受入を省略しない。前提はA1・D1で、不足する人には短い補習を付ける。

GitHubの参照開始点はmain。試行前に教材・確認ガイドのコミットを固定し、start.txtのRaw全文を新しい通常チャットへ貼り付ける。通常利用のPRは該当なし、未マージ版だけ実在PR・head branch・コミットを記録する。開始文をコピーした際を含め、設問・助言・解説の既見を確認する。公開開始文は厳格な試験の秘匿機構ではない。

初回20分は目安。Q1の原回答を保持してから固定助言F01、Q2の修正と理由、Q3の適用範囲、別場面X01へ進む。必要に応じて分割する。初回答が正しい人に誤答や不要な修正を要求しない。ヒント・例・説明は利用可能で、支援利用自体は減点しない。主課題中は遅延課題Y01・Y02を提示しない。

変更するのは新規チャットと承認済み非公開記録だけ。社員・顧客の実資料、過去の回答、確定評価、公開教材、Google/GitHub設定は変更しない。指示は技術的な権限制御ではなく、外部操作を試す演習でもない。

## 記録と次の確認
[学習記録](../../templates/learning-record.md)にQ1・F01・全追加支援・Q2・Q3・X01を別記し、本人の修正理由を短く残す。DX01はA1/B1の別課題であり、W-E2の前後比較には使わない。E2の統合確認には[DX06](../../assessment/practice/DX06.md)があるが、実際に用いた課題・場面IDで記録する。D-E2の単独診断は今回制作していない。

Y01・Y02は確認担当者が別日に提示する。既見、実際の間隔、支援を記録し、未実施や保持を推測で補わない。期待する成果は、指摘理由を使った本人の修正と別場面での根拠である。一度の正答やAIの講評だけで習得・人格・採否を確定しない。

## 中止と復旧
「記録」「中断」「終了」で止め、AIの記録案を原回答と照合する。指摘前の回答を書き換える、正しい行まで変更を強いる、資料を改変する、実行していない保存を報告する場合は試行を止める。原回答と再現条件を非公開に残し、[確認ガイド](../../assessment/practice/feedback-intake-reviewer-guide.md)と照合する。

原回答が欠けた場合は未確認とし、推測復元しない。教材の訂正は[変更手順](../../CONTRIBUTING.md)に従ってPRで行い、承認済みの旧版があれば参照して修復する。適合・承認済みの版がなければ担当者の検証段階に留める。全12能力の教材が揃うことと、全社員配付の承認は別である。
