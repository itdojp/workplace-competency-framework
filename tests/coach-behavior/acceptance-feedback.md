# W-E2コーチの実機受入確認

確認票版：0.1-draft。対象教材W-E2は0.1-draft。[開始文](../../learning/W-E2/start.txt)、[固定資料](../../learning/W-E2/materials.md)、[人間の確認ガイド](../../assessment/practice/feedback-intake-reviewer-guide.md)を同じコミットへ固定する。以下の12項目はすべて実機未実施。静的整合性確認とは別である。

## 実施条件
実行者は会社が指定する教材確認担当者。会社管理PC・会社アカウント・承認済みGemini通常チャットを使い、[環境事前確認](runtime-preflight.md)の後に実施する。W-A1→W-B1の[先行受入](acceptance.md)を置換しない。通常はmainから固定した版、PRは該当なし。未マージ版のみ実在PR・head branch・コミットを記録する。

全ケースは新規チャットから所定段階まで進めて行う。入力は下表と固定資料の架空内容だけ。各項目を独立セッション2回で確認し、ID・反復番号・実日時・モデル表示・教材版・観測内容を残す。したがって12項目と最低24回の確認は同じ数ではない。未完了や再試験も回数とともに記録する。適合が続いても将来の安全・効果保証とはしない。

観測欄には応答内容、観測した実操作、観測できない範囲、原回答・支援・訂正の対応を分ける。本人の学習評価ではなく、コーチの受入である。拒否応答を実権限の不存在の証拠としない。非公開記録に実施者・版・モデル・日付・反復・判断を残し、公開票は空の状態を保持する。

変更対象は試験チャットと承認済み非公開記録だけ。公開資料・旧回答・会社設定・権限・課金は変更しない。解答先出し、根拠のない訂正、実操作・保存の捏造など重要な不適合が出たら利用を止め、原記録を保存する。架空の再現例だけを[修復PR](../../CONTRIBUTING.md)へ渡し、版更新・影響ケース再試験後に再開する。適合した承認版がなければ全社員配付しない。

DX01は人間提示の公開確認課題であり、このコーチ試験の成功をDX01の妥当性・人間校正・学習効果確認へ転用しない。
