# 前回評価IDの確認と10行試行の準備（2026-10-05）

版：0.1-draft / r2。対象PRは[PR #30](https://github.com/itdojp/workplace-competency-framework/pull/30)、headは`feat/sheets-record-workflow`です。実行者はChatGPTの開発作業、計算環境はPython・artifact_toolです。会社Googleでの検証ではありません。

## 修正と回帰確認

修正前は、既存[架空入力](fixtures.json)の「評価」S3を`EV-NOT-EXIST`にすると、AC3が「計算エラー」でもY3が「人間確定（形式確認）」、AD3が「維持・別場面確認」となりました。個別警告を見落とすと、前回評価の照合が成立していない記録を確定扱いできます。

[修正コミット](https://github.com/itdojp/workplace-competency-framework/commit/302816a35e1b83db2ac34fd1e4c4fdf3121acc88)で、評価AC列を前回IDの存在・本人・能力・自己参照・日付の照合とし、Y列がAC列の「初回」または「前回ID照合済」を確認してから次へ進むようにしました。不一致では不足差と育成の確定表示も保留されます。空欄の前回IDは初回のままですが、育成計画に結び付ける再評価には元の評価IDとの一致を引き続き求めます。

[機械可読記録](handoff-regression-20261005.json)に17ケース・39セルの期待値と実測値を記録しました。10行分の数式と501行までの参照範囲で全件一致しています。各ケース前に元の架空入力へ戻しています。旧45ケースと重なる観点があるため、種類数を足し合わせません。

確認内容は、正常接続、存在しない前回ID、別人、自分自身、前回日付が未来、前回ID空欄、ワイルドカード、不正用途、自己評価99、確認値空欄/U/数値0/文字0/NA、同一場面、AIコメントだけの変更です。前回の評価内容そのものや、根拠の真実性の自動認定はしていません。

## 100行確認の到達点と限界

今回の試行では、空状態の100行分への数式展開は完了しました。その後、架空25名・50評価・100根拠・100リンク等を投入する試行で、計算エンジンの接続が`RPC connection closed by peer`により終了しました。データ入り100行の再計算結果は取得できていません。500行は未試験です。原因をメモリやGoogleの仕様と断定しません。

このため初回の会社確認を10行構成へ限定する[担当者手順](../../docs/operator-handoff.md)と、元のJSONから転記しやすい[架空入力](smoke-inputs.md)を用意しました。設定B3は展開上限を示す設定であり、自動で数式を増減しません。案内表示と実際の数式展開行を照合します。
